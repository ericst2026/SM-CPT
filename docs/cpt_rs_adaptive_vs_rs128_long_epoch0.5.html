rs_adaptive_long vs rs128_long at 0.5 epoch

The two runs see the same ~460 M training tokens by their 0.5-epoch checkpoint. rs128_long uses a uniform rank of 128. rs_adaptive_long uses a per-layer, per-module rank plan with about the same number of parameters (79.1 M vs 80.7 M). This page compares their scores and lists every setting that matches or differs.

Inputs. runs/cpt_qwen06b_rs128_long/epoch0.5 (step 6,420) and runs/cpt_qwen06b_rs_adaptive_long/epoch0.5 (step 2,395). Scores come from eval_results/<run>_epoch0.5/. Base scores come from eval_results/cpt_qwen06b_r128_full_epoch0, which both runs copy as their epoch-0 reference. Every Δ is paired over the same questions: MMLU, MCQ and DS-1000 use an exact McNemar test with a normal 95% CI; open QA uses a Wilcoxon signed-rank test. Colour means p < 0.05. The losses have no per-item data, so they are plain differences.

Bottom line

  1. At 0.5 epoch the two adapters can’t be told apart on MMLU. Both lose about 0.7 pt against base (−0.66 pt, p = 0.03; −0.70 pt, p = 0.03). Head to head, adaptive minus rs128 is −0.04 pt (p = 0.91), with 667 questions gained and 672 lost. So far, putting 78% of the rank budget into the MLP has not reduced forgetting.
  2. On the AI-related subjects, adaptive is ahead, but not significantly. rs128 drops 1.9 pt against base (p = 0.04). Adaptive drops 1.0 pt (p = 0.29). The gap between them is +0.9 pt (p = 0.25). Almost all of it comes from machine_learning: 35.7% → 44.6% (+8.9 pt, p = 0.02). That subject has only n = 112, and it is 1 of 57 subjects tested. It would not survive a multiple-comparison correction.
  3. MCQ and DS-1000 are a tie. rs128 gets 62/186 MCQ questions right and adaptive gets 59/186 (p = 0.55). Both pass about 1% of DS-1000.
  4. The losses match to the third decimal, even though adaptive made 2.7× fewer optimizer updates. CPT val losses differ by at most 0.003, and the SFT val loss is 1.5605 vs 1.5624. Adaptive reached the same per-token fit with 2,395 updates of ~187 k tokens, where rs128 used 6,420 updates of ~70 k tokens.
  5. The open-QA numbers can’t be compared across the two runs. rs128_long generated its open-QA answers from Base + adapter, which produced degenerate text (664/984 answers). rs_adaptive_long generated from the chat model Qwen3-0.6B + adapter. Against its own chat reference, the adaptive adapter left ROUGE-L and token-F1 unchanged and made answers 56 words shorter. A like-for-like comparison would need the rs128 epoch-0.5 adapter re-evaluated on the chat model (open_qa only, ~25 min of GPU time). That should wait until the current training run finishes.
  6. The comparison is confounded. Besides the rank plan, the adaptive run also changed gradient accumulation (3 → 8) and left out 148 noisy long documents (−4.6 M tokens, −0.5%). Any difference that does show up at epoch 1 can’t be credited to the rank plan alone.
